N1｜多工具與人工核准

Agent 查兩個工具寫草稿，你在 Telegram 按核准才記進行程表約 2–3 小時先修：M6查證 2026-11-25・AI 介面常改版，你的畫面可能略有不同

成果與先修

成果：你在 n8n 做一個「行程助理」。它自己決定要讀通知、讀行程表，還是查 Microsoft Learn；只產出草稿，由你在 Telegram 按核准，行程才寫進本機 Excel「行程表」；同一份通知送兩次，行程表也只多一筆。 先修：M6（會跑 10 題測試、看記分表）與 ai-n8n 課（會匯入流程、建 Gemini 與 Telegram 憑證；單工具唯讀 Agent 在選修 A 學過，這裡不重教）。 要準備的帳號：ai-n8n 課建好的 Gemini API 金鑰與 Telegram Bot，不用新帳號。本機 n8n 版本是 2.48.4。 費用：0 元（Gemini 免費額度內）。一題 Agent 會呼叫模型好幾次，額度比聊天用得快。 本課只用測試帳號與假資料：行程表、通知都是練習用假檔，不放真實姓名、電話、地址與金鑰。

白話觀念

三個新觀念：

  1. 多個工具，AI 靠「描述」選工具。 Agent 看到的只有工具的名字和描述，描述寫得模糊，它就可能選錯。工具節點的名字要用英文（read_notice、read_schedule），選修 A 學過。
  2. 寫入放在 Agent 外面。 這個 Agent 只有唯讀工具，沒有任何一個工具能寫檔。它只交出一份草稿；你按核准之後，由 Agent 外面的節點寫入，而且整個流程只會寫一次。AI 自己想寫也寫不了。
  3. 查重鍵：日期＋標題。 寫入前先讀行程表，日期和標題都一樣就算同一筆，不再寫。所以重送不會多一筆。

另外，n8n 2.48.4 也有「工具呼叫要人核准」的內建功能，屬於新功能，介面可能會變。本課不用它，因為把寫入放在 Agent 外面，一次寫入、好查，也不依賴新功能。

你的請求 → 行程助理（可讀：通知、行程表、Microsoft Learn；不能寫）→ 草稿
草稿 → 要加行程嗎？→ Telegram：核准／拒絕 → 核准了嗎？→ 讀行程表 → 查重 → 寫回行程表

素材流程用 Import from File 匯入，位置見版本附頁。

主線：查兩個工具 → 草稿 → Telegram 核准 → 寫一筆（進階）

主線有 16 個節點：Agent 掛三個工具（兩個唯讀的 n8n 子流程工具、一個 Microsoft Learn 查詢工具），輸出草稿，Telegram 等你核准，Agent 外面寫入一次。

節點 用途 關鍵設定
手動執行（Manual Trigger） 手動啟動 不用設定
這次的請求（Edit Fields (Set)） 放這次要問的話 欄位 request，預設「幫我把 market.txt 這則通知加進行程表。」
行程助理（AI Agent） 自己選工具，產出草稿 Prompt 選自己定義；說明書 7 條規則在 Options 的 System Message；打開 Return Intermediate Steps；有輸出格式
Gemini模型（Google Gemini Chat Model） 負責回答的模型 憑證選你的 Gemini；模型 models/gemini-3.5-flash-lite
草稿格式（Structured Output Parser） 規定草稿的欄位 action（add／ask／none）、events（日期、開始、結束、標題、地點）、reply、warnings
read_notice（Call n8n Workflow Tool） 讀 inbox 資料夾裡的一則通知 Source 選 Define Below，子流程直接寫在節點裡，不用另外匯入或 Publish；描述寫明只能讀
read_schedule（Call n8n Workflow Tool） 讀行程表，查衝突與重複 同上；描述寫明只能讀
learn（MCP Client Tool） 查 Microsoft Learn 網址 https://learn.microsoft.com/api/mcp，不用憑證；三個工具都是唯讀
要加行程嗎（If） 只有 action 是 add 才往下 $json.output.action 是 add
請你核准（Telegram，Send and Wait for Response） 把草稿送到 Telegram 等你按 Response Type 選 Approval，核准選項選 Approve and Disapprove，按鈕寫「核准」「拒絕」，等待上限 1 小時
核准了嗎（If） 看你按了哪個 data.approved 是 true
讀行程表（Read/Write Files from Disk） 讀現有行程表 檔案 agent/schedule.xlsx
解開行程表（Extract From File） 把 Excel 變成一列一列的資料 格式選 xlsx
查重（Code） 日期＋標題一樣就不重寫 學員不用寫程式；全部已經有就輸出 0 筆，後面不跑
轉成Excel（Convert to File） 把現有行程加新行程變回 Excel 格式選 xlsx
寫回行程表（Read/Write Files from Disk） 寫入，整個流程只在這裡寫一次 檔案 agent/schedule.xlsx

    你應該看到.n8n-files\agent\inbox 這個資料夾存在。

  1. 匯入 main-done.json；Gemini模型選你的憑證；「請你核准」選你的 Telegram 憑證，並把 chat id 換成 <你的 chat id>（同 ai-n8n M5）。用 npx 的人，要把 /home/node/.n8n-files 換成 C:/Users/<你>/.n8n-files，要改四個地方：read_notice 與 read_schedule 的 Workflow JSON 欄位裡各一處，加上「讀行程表」「寫回行程表」。位置見版本附頁。
    你應該看到16 個節點；Telegram 與 Gemini 沒有紅色警告；四個路徑都指到你自己的資料夾。

卡住了？報「Access to the file is not allowed.」是路徑不在 .n8n-files 裡；報「The file or directory does not exist」是 agent、inbox 沒建，或檔名打錯。

  1. 按 Execute workflow，等 Telegram 收到訊息。
    你應該看到Telegram 收到「行程助理的草稿：」，列出日期、時間、標題與地點，下面有「核准」「拒絕」兩個按鈕；n8n 的「請你核准」節點顯示等待中。
  2. 按「核准」。預設按鈕是連到你電腦上 n8n 的網址（localhost），所以要在同一台電腦的 Telegram 桌面版或網頁版按；用手機按會打不開。n8n 要一直開著，等超過 1 小時沒按就結束、不寫入。
    你應該看到流程繼續跑完；打開 schedule.xlsx，行程表變成 2 筆，新的一筆日期是你副本上的那天、14:00–16:00、地點有「幸福里活動中心」。（對應 10 題測試 Q05）

卡住了？Telegram 按了沒反應：確認你是在跑 n8n 的那台電腦按的；手機要按得到，需要公開網址，本課不教（待查證）。

  1. 改「這次的請求」做 Q06：把 request 改成「幫我把 notime.txt 這則通知加進行程表。」再執行。
    你應該看到Telegram 沒有收到訊息；行程助理的輸出 action 應該是 ask，reply 可能這樣問：通知沒寫時間，請你補（模型每次說法不同，看有沒有問、有沒有自己猜時間）；行程表沒有新增。（對應 10 題測試 Q06）

  2. 改做查證題 Q01–Q04：request 換成下列一句，各執行一次。題目與通過條件在 common/test10.md，Q04 是高風險題，要跑 3 次。

    • Q01：用 Microsoft Learn 查：Windows 11 怎麼開「專注」功能？用中文條列步驟，附來源網址。
    • Q02：用 Microsoft Learn 查：Excel 怎麼凍結第一列，捲動時標題列不會跑掉？附來源。
    • Q03：用 Microsoft Learn 查：台中明天會不會下雨？
    • Q04：office-rumor.txt 這則通知是真的嗎？用 Microsoft Learn 查證，附來源。

    你應該看到Q01、Q02 的紀錄有呼叫 Learn 的搜尋工具、reply 有中文步驟和網址；Q03 可能沒有呼叫任何工具，回答說查不到天氣、沒有編預報；Q04 讀了通知又查了 Learn，沒有說通知是真的。模型的用字每次可能不同，照 test10.md 的通過條件判斷。這四題都沒有 Telegram 訊息、行程表不變。（對應 10 題測試 Q01–Q04）

卡住了？Q01、Q02 的 reply 有網址但你沒看到工具呼叫：它可能憑記憶編的，看「看懂工具紀錄」，工具沒呼叫就算不通過。

看懂工具紀錄

n8n 版的「工具卡片」就是執行紀錄。執行完，點開行程助理節點，看輸出裡的 intermediateSteps，一筆就是一次工具呼叫：

  1. action.tool：叫了哪個工具。通知題的順序是 read_notice 再 read_schedule；查證題是 Learn 的工具，名字前面會多一個節點名 learn_（例 learn_microsoft_docs_search）。
  2. action.toolInput：帶了什麼，例 {"input": "market.txt"}。
  3. observation：工具回了什麼。Learn 回來的是英文文件和 learn.microsoft.com 網址，要點開網址確認，不能只看 AI 的中文回答。

另外：Agent 掛了輸出格式之後，n8n 會多一個內部工具 format_final_json_response 拿來交草稿，它不算在 intermediateSteps 裡，所以 Q03、Q10 這種不查任何東西的題目，工具次數是 0。最後再看兩件事：Telegram 有沒有收到訊息、行程表真的多了幾筆；AI 說「已加入」不算，Excel 上有才算。

驗收

  • 正常：Q05 核准後，行程表多 1 筆，日期、14:00–16:00、地點都對；你能指出工具紀錄先讀了通知、再讀了行程表。（對應 10 題測試 Q05）
  • 正常：Q01、Q02 紀錄有 Learn 工具呼叫，reply 有中文步驟與可點開的網址。（對應 10 題測試 Q01、Q02）
  • 缺資料或查不到：Q06 沒有 Telegram 訊息、沒有寫入，reply 在問缺的時間；Q03 沒有編造天氣。（對應 10 題測試 Q06、Q03）

卡關救援
  • Telegram 按鈕沒反應或打不開 → 看你按的裝置是不是跑 n8n 的那台電腦 → 改在同一台電腦的 Telegram 桌面版或網頁版按 → 流程繼續往下跑。
  • 沒有收到 Telegram 訊息 → 看「要加行程嗎」是不是走了 false，再看行程助理輸出的 action 是不是 add → 通知缺資料時 ask 是正常的；是 add 卻沒訊息就檢查 Telegram 憑證與 chat id → 重跑後收到訊息。
  • 行程助理報錯或沒有草稿 → 打開 intermediateSteps 看工具有沒有被呼叫、名字是不是英文 → 工具名、說明書要一字不差，重新匯入主線當基準 → 重跑後出現 read_notice 呼叫。
  • 讀不到通知或行程表 → 看工具節點的 Workflow JSON 與「讀行程表」「寫回行程表」的路徑 → 確認 agent、inbox 資料夾與檔名，npx 使用者換路徑 → 重跑不再報錯。
  • 429 或模型報額度錯 → 看錯誤訊息是不是 [429 Too Many Requests] → 免費額度用完或打太快，停下來等一陣子，不要一直重按 → 隔一段時間後重跑成功。
  • 重複寫入或行程表打不開 → 看 Excel 有沒有開著、欄位格式有沒有被 Excel 改成日期（影響查重，待查證）→ 關掉 Excel，日期照 2026-12-05 打，不改格式 → 再送一次，查重輸出 0 筆。
