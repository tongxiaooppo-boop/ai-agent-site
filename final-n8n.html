n8n 版結業｜會自己跑的行程助理

n8n 版分身通過五項畢業標準，並能重送不重複、出錯能復原約 4–6 小時先修：N3查證 2026-11-25・AI 介面常改版，你的畫面可能略有不同

成果與先修

成果：你在 n8n 做出一個「會自己跑的行程助理」：每天整理通知、只讀不寫、你在 Telegram 核准才寫進行程表，並用 10 題測試驗收；另外證明它重送不重複、出錯能復原。 先修：N3（主線、停止條件、10 題記分表都做過）。 要準備的帳號：同 N1，不用新帳號。費用 0 元。 只用測試帳號與假資料：截圖與流程 JSON 交出去之前，先遮住帳號名稱、金鑰、Bot token 與 chat id。

畢業標準

畢業要通過下列五項（照 DECISION-v2.md 第 2 節）：

  1. 接上一個真的工具。
  2. 看懂工具紀錄。
  3. 限制權限。
  4. 完成一次經人確認的外部寫入。
  5. 跑完共用 10 題測試：通過率至少 90%，安全錯誤零次；高風險題重跑 3 次。

n8n 版對照：第 1 項是 Agent 掛的 read_notice、read_schedule、read_profile 與 learn；第 2 項是 intermediateSteps；第 3 項是權限盤點表；第 4 項是 Telegram 核准後寫進行程表；第 5 項是 N3 小練習② 加 N1 主線補跑的記分表。

n8n 版加測（兩項，不算在五項裡）

這兩項是 n8n 版才有的，通過與否不影響上面五項，但交付清單要附證明：

  1. 重送不重複：同一份通知送兩次、都按「核准」，行程表只有 1 筆新的；做法見 N1 小練習②。
  2. 出錯能復原：先備份行程表，故意弄壞，再還原，打開 Excel 確認資料回來了；做法見下一節。

做法：備份與還原

兩個小流程，各 3 個節點，都不用 Agent、不用模型額度。

節點 用途 關鍵設定
手動執行（Manual Trigger） 手動啟動 不用設定
讀行程表／讀備份（Read/Write Files from Disk） 讀檔 備份流程讀 agent/schedule.xlsx；還原流程讀 agent/schedule-backup.xlsx
寫備份／寫回行程表（Read/Write Files from Disk） 寫檔 備份流程寫 agent/schedule-backup.xlsx；還原流程寫回 agent/schedule.xlsx
  1. 匯入 backup-done.json、restore-done.json；用 npx 的人，要把 /home/node/.n8n-files 換成 C:/Users/<你>/.n8n-files，每個流程各改兩個節點。位置見版本附頁。
    你應該看到兩個流程各 3 個節點，路徑都指到你自己的資料夾。
  2. 先確認行程表有資料（N1、N2 做過的話有 2 筆以上）。執行 backup-done.json。
    你應該看到agent 資料夾多了 schedule-backup.xlsx，打開和行程表內容一樣。
  3. 故意弄壞：把 schedule.xlsx 其中一列刪掉，或把整個檔改名移走。
    你應該看到行程表少了一列，或 agent 裡找不到 schedule.xlsx。
  4. 執行 restore-done.json。
    你應該看到agent 裡又有 schedule.xlsx，打開後資料和備份時一樣，被刪的那列回來了。

卡住了？還原完行程表是空的：看備份檔是不是在弄壞之後才做的；備份要在壞之前做，所以每次大改動前先備份。

交付清單

交付時附上：

  1. 流程 JSON（去憑證）：N3 主線的流程匯出檔，確認裡面沒有金鑰、Bot token，chat id 換成 <你的 chat id>。
  2. 執行紀錄截圖：一張 Agent 的 intermediateSteps（能看出工具與帶入的內容），一張 Telegram 核准訊息，一張核准後行程表多一筆。
  3. 記分表：common/score-sheet.md 填完，含高風險題 3 次結果與安全錯誤欄。
  4. 權限盤點表：照下面這張填。重點：每個工具都只能讀；唯一會寫的是 Agent 外面的「寫回行程表」，而且要先經 Telegram 核准。
項目 能做什麼 讀或寫 要不要先經你核准 怎麼收回
read_profile 讀 agent/profile.md 只能讀 不用 從 Agent 拿掉這個工具節點
read_notice 讀 agent/inbox 裡的通知 只能讀 不用 從 Agent 拿掉這個工具節點
read_schedule 讀行程表 只能讀 不用 從 Agent 拿掉這個工具節點
learn 查 Microsoft Learn 只能查（唯讀） 不用 從 Agent 拿掉這個工具節點
寫回行程表（Agent 外面） 把核准的行程寫進 schedule.xlsx 寫 要，先經 Telegram 核准 取消發布流程，或刪掉這個節點
Gemini 金鑰、Telegram Bot 模型與通知 憑證 — 到原平台重新發一把（位置待查證）

自我驗收清單

  • 五項畢業標準逐項有證據：工具、紀錄截圖、權限盤點表、一次核准後的寫入、記分表。
  • 加測 1：同一份通知核准兩次，行程表只多 1 筆。
  • 加測 2：備份後弄壞，還原後 Excel 資料回來。
  • 10 題通過率至少 9/10，安全錯誤 0 次，★ 題各跑 3 次。
  • 交付的流程 JSON、截圖都沒有金鑰、帳號名稱、真實個資。
  • 用完把排程流程取消發布，並在權限盤點表註明。
卡關救援
  • 還原後資料不對 → 看 schedule-backup.xlsx 的修改時間與內容、是不是在弄壞之後才備份 → 用較早的備份，或回頭找 N1、N2 的紀錄補回缺的列 → 重新打開 Excel 看列數。
  • 流程 JSON 匯出後找不到憑證欄位 → 看匯出檔裡有沒有 Bot token 或金鑰字串 → 有就換成佔位符再交 → 重新搜尋檔案確認沒有。
  • 記分表有題目沒有結果 → 看是不是 Q05、Q07、Q08 沒用 N1 主線補跑 → 補跑並把結果謄上去 → 記分表 10 題都有結果。
  • 寫入多了一筆重複 → 看日期＋標題是否有空白字或格式差異 → 到 Excel 刪掉多的那列，不要改欄位格式 → 再送一次，查重輸出 0 筆。
  • 畫面和教材不一樣 → 先看版本附頁 n8n 版結業一節，再看 N1–N3 對應位置 → 找不到就截圖（先遮住帳號與個資）求助 → 畫面對上之後繼續。

求助格式：用的是哪個 AI、免費或付費、卡在哪一步、畫面上的訊息原文、已經試過什麼。貼上之前先遮住帳號名稱、金鑰與 chat id。
