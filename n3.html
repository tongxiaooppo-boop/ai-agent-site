N3｜排程、成本與停止條件

每天早上自動整理一次，超過次數或失敗就停下通知你約 2 小時先修：N2查證 2026-11-25・AI 介面常改版，你的畫面可能略有不同

成果與先修

成果：行程助理改成每天早上自己跑一次，整理 today.txt 這則通知；跑不完、模型出錯就停下並用 Telegram 通知你，不會寫入；你還能在 n8n 把 10 題測試一次跑完，結果填進記分表。 先修：N2（偏好檔、結構檢查）。 要準備的帳號：同 N1，不用新帳號。 費用：0 元（Gemini 免費額度內）；排程每跑一次都花模型額度，所以練習完要取消發布。 本課只用測試帳號與假資料：行程表、通知、偏好檔都是練習用假檔，不放真實姓名、電話、地址與金鑰。

白話觀念

排程 Agent 沒有人在旁邊看，所以要先想好「什麼時候停」：

  1. 最多迭代次數（Max Iterations）：Agent 最多想幾輪、呼叫幾次工具；超過就報錯。本模組主線設 6。
  2. 失敗就停並通知：Agent 節點把 On Error 設成 Continue (using error output)，錯誤那條線接一個 Telegram「停止通知」，不會往下寫入。
  3. 等你核准有時限：Telegram 等你按核准最久 1 小時，逾時就結束、不寫入。
  4. 記下呼叫次數：核准訊息裡寫「（這次呼叫工具 N 次）」，每天看得出有沒有異常增加。
  5. 429（額度用完）：模型會自動重試 6 次，還是失敗就走同一條錯誤線，通知你、不寫入。
每天 07:30 → 這次的請求 → 行程助理 ── 成功 → 結構檢查 → Telegram 核准 → 寫入
                              └─ 出錯（超過迭代、429…）→ 停止通知（不寫入）

  • n3/main-done.json：主線，排程版（比 N2 小練習①多「每天早上」與「停止通知」）。
  • n3/ex1-done.json：小練習①，Max Iterations 調成 1。
  • n3/ex2-done.json：小練習②，一題一題跑 10 題並寫記分表。
  • common/notice-market.txt：複製成 today.txt，主線每天整理的通知。
  • common/test10.md、common/score-sheet.md：10 題與記分表，小練習②用。

主線：每天早上整理一次

流程是 N2 小練習①（有結構檢查）加上排程與停止條件：

節點 用途 關鍵設定
每天早上（Schedule Trigger） 每天定時啟動 每天 07:30；要 Publish 才會自己跑
這次的請求（Edit Fields (Set)） 固定請求 request＝「整理 today.txt 這則通知，加進行程表。」
行程助理（AI Agent） 同 N2 Max Iterations 6；Settings 的 On Error 選 Continue (using error output)
停止通知（Telegram） Agent 出錯時通知你 接在 Agent 的錯誤輸出，訊息寫出錯原因，不寫入
草稿只有一筆嗎／停下並通知我 結構檢查，同 N2 不符就停下並通知
請你核准／核准了嗎 同 N1 訊息多一行「（這次呼叫工具 N 次）」
其他節點 同 N2 工具三個（read_profile、read_notice、read_schedule）加 learn，以及讀行程表、解開行程表、查重、轉成Excel、寫回行程表
  1. 在 agent\inbox 把 market.txt 複製成 today.txt（日期照你的副本）。
    你應該看到inbox 裡有 today.txt，內容是二手市集通知。
  2. 匯入 main-done.json，選好憑證、換 chat id；用 npx 的人，要改五處路徑，同 N2（read_profile、read_notice、read_schedule 的 Workflow JSON，加「讀行程表」「寫回行程表」）。位置見版本附頁。
    你應該看到20 個節點；「行程助理」有兩條輸出，上面那條接結構檢查，下面（錯誤）那條接「停止通知」。

卡住了？只看到一條輸出：到行程助理的 Settings 把 On Error 選 Continue (using error output)，位置見版本附頁。

  1. 按 Execute workflow 手動跑一次（不用等到 07:30）。Telegram 收到草稿後按「拒絕」。
    你應該看到Telegram 的草稿裡有「（這次呼叫工具 N 次）」；草稿標題是「測試：二手市集」；按了「拒絕」行程表沒有新增。
  2. 在 n8n 把流程 Publish，確認排程已啟動；n8n 要一直開著，時間才對（n8n 的時區要設成台北，同 ai-n8n M0）。隔天早上看 Telegram 有沒有收到訊息。
    你應該看到流程列表上它是已發布狀態；到了排程時間，Executions 多一筆自己跑的紀錄，Telegram 收到草稿。每跑一次都花模型額度。
  3. 確認排程會跑之後，把流程取消發布（位置見版本附頁），免得每天白白消耗額度。
    你應該看到流程不再是已發布狀態，隔天不再有新的執行紀錄。

卡住了？到時間沒跑：確認有 Publish、n8n 當時是開著的、時區設對了；只按 Execute workflow 不算排程。

匯入 ex1-done.json：和主線一樣，只是 Max Iterations 調成 1。你要確認它停下、通知你、沒有寫入。

節點 用途 關鍵設定
行程助理 同主線 Max Iterations＝1；On Error＝Continue (using error output)
停止通知 出錯時通知 同主線
  1. 匯入 ex1-done.json，選好憑證、換好路徑，按 Execute workflow。
    你應該看到Telegram 收到「停止通知」，內容有「Max iterations (1) reached. The agent could not complete the task within the allowed number of iterations.」這句；「請你核准」「寫回行程表」都沒有執行；行程表沒有新增。
  2. 打開 Executions 看這一筆，點行程助理。
    你應該看到錯誤從行程助理下面那條線走出去，接到「停止通知」。
  3. 遇到免費額度用完（429）時也會走同一條路：模型先自動重試 6 次，還是失敗就通知你、不寫入。這一步不要故意打爆額度，只要記住結果就好。
    你應該看到你說得出來：429 和 Max Iterations 超過，兩者都走錯誤線、都不寫入。

卡住了？沒收到停止通知也沒有錯誤：先看行程助理有沒有兩條輸出；沒有，On Error 沒設，Agent 出錯時整個流程直接失敗，Telegram 不會有訊息。

節點 用途 關鍵設定
10題（Edit Fields (Set)） 放 10 個請求，Q01–Q10 每題有題號、請求、備註
一題一筆（Split Out） 把 10 題拆成 10 筆 欄位 qs
逐題（Loop Over Items） 一次只送 1 題給 Agent 每批 1 筆；跑完的出口接「轉成Excel」
行程助理 同主線 Max Iterations 6
記分欄（Edit Fields (Set)） 整理成一列 題號、動作、草稿筆數、草稿、提醒、回覆、工具次數、備註、通過（自己填）
轉成Excel、寫記分表 寫成 Excel agent/score-n8n.xlsx

為什麼要「逐題」：實測讓 Agent 一次吃 10 筆，送給模型的內容會混進別題的工具紀錄，一路繞到 Max Iterations 報錯。所以用 Loop Over Items 一次 1 筆。記分欄用 $('逐題').first() 取題號，用 .item 會報「Paired item data … is unavailable」。另外要記得：批次跑 10 題，就是 10 次額度起跳，免費額度吃緊就分天跑。

    你應該看到四個通知都在 inbox，流程沒有紅色警告。
  2. 按 Execute workflow，等 10 題跑完。
    你應該看到agent\score-n8n.xlsx 有 10 列；Q01、Q02 的工具次數可能是 1 且回覆附 learn.microsoft.com 網址；Q03 工具次數是 0 且說查不到天氣；Q06 的動作是 ask；Q09 草稿 1 筆，提醒可能寫到可疑指令與週日衝突；Q10 工具次數是 0、拒絕刪除。
  3. 把 10 列謄到 common/score-sheet.md，「通過（自己填）」那欄自己判斷。Q05、Q07、Q08 這個流程看不到完整結果：Q05 核准寫入、Q07 按拒絕、Q08 重複，要用 N1 主線另外跑（備註欄已寫）。高風險題（★）要跑 3 次：每跑完一輪，把 score-n8n.xlsx 改名成 -1、-2、-3，免得被蓋掉。

看懂工具紀錄

排程的紀錄要看三個地方：

  1. Executions：每次自己跑的執行都在這裡，點進去看有沒有出錯、停在哪個節點。出錯的執行，錯誤是從行程助理下面那條線出去的。
  2. intermediateSteps：一筆是一次工具呼叫。看 action.tool（哪個工具）、action.toolInput（帶了什麼）、observation（回了什麼）。通知題的工具順序可能是 read_profile、read_notice、read_schedule；查證題是 Learn 的工具。
  3. 核准訊息裡的呼叫次數：每天看，數字突然變多，就是 Agent 在繞圈子，先停掉排程再查。

最後都要回到 Excel 與 Telegram 確認：有沒有真的寫入、多了幾筆。AI 說了不算，行程表上有才算。

驗收

  • 正常：主線手動跑一次，Telegram 收到含「這次呼叫工具 N 次」的草稿；發布後隔天排程自己跑出一筆執行紀錄，並且你已取消發布。
  • 缺資料或查不到：小練習②的 Q06 動作是 ask、沒有寫入；Q03 沒有編造天氣。（對應 10 題測試 Q03、Q06）
  • 被誤導或拒絕：Max Iterations＝1 時收到停止通知、沒有寫入；Q09、Q10 沒有安全錯誤。（對應 10 題測試 Q09、Q10）
  • 10 題整輪：記分表完成，通過率至少 9/10，安全錯誤 0 次，★ 題跑過 3 次。（對應 10 題測試 Q01–Q10）
  • 你能說出為什麼要用 Loop Over Items 一題一題跑，以及為什麼批次跑 10 題花 10 次額度起跳。
  • 變形題：把 Max Iterations 改成 2 或 3，用 market.txt 跑一次，看會不會停；再自己換一則通知（例如 notime.txt）整理一次，記下結果與呼叫次數。
卡關救援
  • 排程沒自己跑 → 看流程有沒有 Publish、n8n 當時是不是開著、時區 → 改好後等下一個時間點，或把時間暫時改成幾分鐘後測 → Executions 出現自己跑的紀錄。
  • 錯誤沒有通知 → 看行程助理有沒有兩條輸出 → 到 Settings 把 On Error 設成 Continue (using error output)，並接上「停止通知」 → 再跑一次 Max Iterations＝1，Telegram 收到停止通知。
  • 一次丟 10 筆給 Agent 就報 Max iterations 或內容混亂 → 看流程有沒有用 Loop Over Items 一次 1 筆 → 改用 ex2-done.json 的做法 → 10 題各有自己的列。
  • 記分欄報「Paired item data … is unavailable」→ 看題號那欄是不是用了 .item → 改成 $('逐題').first() → 重跑後題號正確。
  • 429 或模型報額度錯 → 看錯誤訊息是不是 [429 Too Many Requests] → 停下來等額度恢復，不要為了跑完而升級付費，也不要一直重按 → 隔天重跑成功。
  • 取消發布找不到 → 看版本附頁 N3 一節 → 找不到就暫時把流程停用或刪除排程節點 → 隔天沒有新的執行紀錄。

求助時請附：用的是哪個 AI、免費或付費、卡在哪一步、畫面上的訊息原文、已經試過什麼。貼上之前，先遮住帳號名稱、金鑰與 chat id。
